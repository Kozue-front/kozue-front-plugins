# Slackフィルタ

大きなチャンネルでは、自分に関係のない発言が多く、読むだけで時間が取られる。この skill は、Slack から**自分宛て・自分がいる会話・自分の担当する話題**の発言だけを拾ってまとめる。

特定のアカウントの発言を、結果から外す設定もできる(自動投稿や、自分の担当と関係のない発言が多い相手など)。外したアカウントの発言は、まとめに出さず、まとめの判断にも使わない。

## 呼び出し方

| 打つ文 | 動き |
|---|---|
| `Slackフィルタ` | 直近24時間を、設定に従ってまとめる |
| `Slackフィルタ 3日` / `Slackフィルタ 10/1〜10/7` | 指定した期間をまとめる |
| `Slackフィルタ設定` | 設定画面を開く |

## 全体の流れ

1. 設定を読む(→ `references/settings.md`)
   - 設定が無い → 手順A(設定画面)のあと、手順B(まとめる)へ
   - 「次に設定画面を開く日」を過ぎている、または「毎回」 → 手順Aのあと、手順Bへ
   - それ以外 → 手順Bへ
2. 「Slackフィルタ設定」と打たれたときは、手順Aだけを行う

## 外したアカウントの扱い(いちばん大事)

外したアカウントの発言が少しでも結果に混ざると、設定した意味が無くなる。ここは他のどの手順よりも優先する。

設定画面と設定の文では、外したアカウントを「除外する人」と呼んでいる。

判定は**表示名ではなく Slack のユーザーID**で行う。表示名は変えられるし、同じ名前の人もいるため。

### モード「ブロック」

そのアカウントがSlackにいないものとして扱う。次はすべて捨てる。

- その人の発言
- その人が立てたスレッド(返信も含めて丸ごと)
- その人宛ての発言(その人へのメンションを含む発言、その人の発言への返信)
- その人の発言を引用・転送した発言
- その人から自分へのDM

捨てたものは、件数も含めて結果に出さない。「〇件除外しました」とも書かない。使う人の目に跡が残らないようにするため。

### モード「場面ごとに決める」

その人の発言を、次の3つの場面に分け、設定に従って扱う。

| 場面 | 判定のしかた |
|---|---|
| ① 自分宛て | 本文に自分へのメンションがある、またはその人から自分へのDM |
| ② 他人宛てだが、自分がいるスレッドの中 | 自分が書いた、または返信したスレッドの中の発言 |
| ③ 自分と関係のない場所 | ①②以外 |

ほかの人による、その人の発言への返信・引用・転送と、その人へのメンションを含む発言は、**その発言が置かれた場面(①②③)と同じ扱い**にする。たとえば③が「消す」なら、関係のない場所でその人の発言を引用した発言も消す。

扱いは3つ。

- **消す**:ブロックと同じく、跡を残さず捨てる
- **確認する**:本文は出さない。「誰から・どのチャンネルで・いつ・どの場面か」とリンクだけを、結果の最後の「確認が必要なもの」に並べる。開くかどうかは使う人が決める
- **残す**:ほかの人の発言と同じように扱う

①の既定が「確認する」になっているのは、相手が誰であっても、自分宛ての連絡には締切や依頼が含まれることがあるため。消すと「頼まれていたのに気づかなかった」という形で、困るのは使う人になる。

### どちらのモードでも守ること

- 外したアカウントの発言(「残す」以外)は、まとめの根拠にも、話題の候補づくりにも、ほかの発言の解釈にも使わない。読んだ内容に引きずられて書いたと疑われる表現も避ける
- 外したアカウントの発言を言い換えて紹介しない。「〇〇という意見もあった」のような形でも出さない
- 迷ったら捨てる側に倒す。拾い忘れは使う人が Slack で確かめられるが、混ざったものは取り消せない

## 手順A:設定画面

1. **自分のIDを確かめる**:Slack の検索や users 系のツールが返す「ログイン中のユーザーID」を使う
2. **前回の設定を読む**(あれば)。画面の初期値にする
3. **話題の候補を作る**:直近7日の「自分の発言」と「自分がいるスレッドの発言」を集める。外したアカウントの発言は、ここで先に取り除く(取り除いてから話題をまとめる。順番が逆だと、その人の発言をもとにした話題が候補に出てしまう)。残った発言を5〜8個の話題にまとめ、それぞれの件数を数える。話題の名前には「、」を使わない(画面から届く文で、話題の区切りに「、」を使うため)。前回選ばれていた話題は、今回の発言に無くても候補に残し、選んだ状態にしておく
4. **画面を出す**:`assets/settings_screen.html` を読み、`__INITIAL_STATE__` を初期値のJSONに置き換えて、会話の中にウィジェットとして表示する(show_widget などのインライン表示の機能を使う)。初期値の形は `references/settings.md` の「画面に渡す初期値」を見る
   - JSONは `<script>` の中にそのまま埋め込まれる。埋め込む前に、`<` を `\u003c`(バックスラッシュ・u・0・0・3・c の6文字)に置き換える(話題の名前は Slack の発言から作るので、`</script>` のような文字が混ざると画面が壊れたり、別の動きを仕込まれたりするため。置き換えてもJSONとしてそのまま読める)
   - ウィジェットを出す機能が無い環境では、画面と同じ5項目を順に質問して答えてもらう
5. **「【Slackフィルタ設定】」で始まるメッセージを受け取ったら**:
   - 外す人の名前を、Slack のユーザー検索でIDに直す。候補が複数あるときや見つからないときは、推測で決めず、候補を出して使う人に選んでもらう
   - チャンネル名をIDに直す
   - 話題ごとに、Slack の検索で使う言葉を2〜4個決める(使う人に入力させない。話題の名前と、候補づくりで見た発言から決める)
   - 次に設定画面を開く日を計算する
   - `references/settings.md` の形で保存し、保存した内容を短く報告する。外した人の名前は報告に繰り返さず「外すアカウント:1人(ブロック)」のように数とモードだけを書く
6. 「Slackフィルタ」から手順Aに来た場合は、保存したら続けて手順Bへ進む

## 手順B:まとめる

1. **期間を決める**:指定が無ければ、今から24時間前まで
2. **集める**:`references/collect.md` の順に、拾う対象ごとに Slack を検索・取得する。設定でチャンネルが決まっていれば、その中だけを見る(自分へのDMは、チャンネルの設定にかかわらず「自分宛て」として見る)
3. **外す**:上の「外したアカウントの扱い」に従う。集めた直後、まとめる前に行う
4. **重複を除く**:同じ発言が複数の拾い方で出てきたら1つにする
5. **出す**:設定の「結果の形」に従う(下の出力の形)

## 出力の形

冒頭に1行で「期間・拾った件数・見たチャンネル」を書く。そのあと:

**要約**:話題ごとに見出しを立て、何が起きたか・自分に何が求められているかを短く書く。自分への依頼や締切は、話題とは別に先頭の「自分宛て」にまとめる。各項目に元の発言へのリンクを付ける。

**発言の一覧**:拾った発言を日時順に並べる。各行は「日時・チャンネル・発言者・本文(長ければ100字で切る)・リンク」。

設定で選ばれている話題のうち、期間内に自分以外の動きが無かったものは、見出しを立てずに「〇〇・△△は、この期間に自分以外の動きがありませんでした」と1行にまとめる。

ボットや自動通知を拾わない設定のときは、最後に「ボットの通知は入れていません(CIの通知 6件、勤怠のリマインド 2件)」のように、件数だけを1行で書く。外したアカウントと違い、ボットは存在を隠す理由が無く、件数が分かれば使う人が「やっぱり拾う」に切り替えられるため。

どちらの形でも、最後に「確認が必要なもの」(場面ごとモードで「確認する」に当たったもの)を、本文なしで並べる。該当が無ければこの節は書かない。

拾った件数が0件なら、「期間内に、自分に関係のある発言はありませんでした」と書き、どこを探したか(チャンネル・拾う対象)を添える。「見つからない」と「存在しない」は違うため。

## 既知の限界

- 発言者のIDが取れない発言は、表示名が外したアカウントの表示名と一致すれば外す側に倒す。そのため、同じ表示名の別の人の発言が外れることがある
- Claude は外したアカウントの発言を一度は読む(読まないと、どれを外すか判定できないため)。結果に出さず、判断にも使わない、という形で外している
